# Internal Presentations

A collection of tools for build reproducible technical
presentations. This project uses pandoc to process markdown files into
slidy presentations. We use plantuml or mermaid to build digrams.

## Install

```shell
brew bundle
```

## Usage

Add a presentation as a markdown file in any top-level folder — name
the folder however makes sense (a topic like `notifications/`, a team,
or a person). `just build-all` builds every `*.md` file in every
top-level folder. Output HTML goes to `build/`, mirroring the source
layout (e.g. `notifications/notifications-storage.md` builds to
`build/notifications/notifications-storage.html`).

Give each deck front matter with `title:`, `author:`, `date:`, and a
one-line `description:` — that's what the site index lists it by.

The quickest start is `just new`, which renders
`templates/presentation.md` into a fresh deck with the front matter
filled in (author from `git config user.name`, date today):

```shell
just new notifications/retry-queues "Retry Queues" "How our retry queues work."
```

```shell
just --list
just build-all
just build-presentation notifications/notifications-storage.md
just clean
```


## Styling

Decks are themed by `templates/oneproject.css`, a Slidy stylesheet
using One Project's design tokens (cream paper, Roboto/Roboto Serif,
amber accents). It's embedded into each built deck, so the output is a
single self-contained HTML file. Retheme by editing the `:root` token
block at the top of the file. Useful extras: `# Title {.dark}` for a
full-bleed dark slide, `::: handout` for speaker notes (hidden on
screen, shown in print), and `::: columns` / `::: column` for
side-by-side layout.

## Website

`just build-site` builds the whole site into `build/`: every deck plus
a `build/index.html` front door. The index's table of talks is
generated by `filters/talks.lua` from each deck's front matter
(`title:`, `author:`, `date:`, `description:`), so it never goes stale.

On every push to `main`, `.github/workflows/site.yml` builds the site
and deploys it to GitHub Pages at
<https://oneprojectorg.github.io/internal-presentations/>. One-time
repo setup (Settings → Pages): set **Source** to "GitHub Actions".

Note: the site is publicly reachable by anyone with the URL. Private
Pages (org-members-only) requires GitHub Enterprise Cloud, which this
org's plan doesn't include — don't put anything sensitive in a deck.

CI installs a pinned PlantUML release rather than Ubuntu's apt package,
which is years old and renders diagrams with the obsolete default
theme. Keep the `PLANTUML_VERSION` in the workflow roughly in step with
what brew installs locally.

## Pandoc

Pandoc is the whole build pipeline. It parses each Markdown deck into a
document tree, hands that tree to the Lua filters in `filters/`, then
writes the result out as a W3C Slidy presentation (`-t slidy`), where
every `#` heading starts a slide. `--embed-resources` inlines the
stylesheet and every rendered diagram, so a built deck is one
self-contained HTML file that works offline.

Each filter rewrites one piece of the tree during the build:

| Filter | What it does |
|---|---|
| `include.lua` | Splices other files in with `!include` (the site index pulls in this readme that way). |
| `diagram.lua` | Runs ```` ```plantuml ```` code blocks through PlantUML and replaces them with the rendered SVG. |
| `check-links.lua` | Verifies `#anchor` and relative-file links at build time, not when a reader clicks. |
| `talks.lua` | On the index page, replaces a ```` ```{.talks} ```` block with a table of every deck, read from front matter. |
| `not-in-format.lua`, `pagebreak.lua` | Format-conditional content and page breaks. |

`--citeproc` adds citation and bibliography processing for decks that
cite sources.

The payoff: the source of truth is plain text, so decks diff and review
like code, and the only tools needed are the three the Brewfile
installs — pandoc, just, and plantuml — the same three CI uses. Even
`just new` scaffolding runs on pandoc's embedded Lua interpreter
(`pandoc lua scripts/new-talk.lua`), so the repo has exactly one
scripting runtime.

# Internal Presentations

A collection of tools for build reproducible technical
presentations. This project uses pandoc to process markdown files into
slidy presentations. We use plantuml or mermaid to build digrams.

## Install

```shell
brew bundle
```

## Usage

Add a presentation as a markdown file in any top-level folder — name
the folder however makes sense (a topic like `notifications/`, a team,
or a person). `just build-all` builds every `*.md` file in every
top-level folder. Output HTML goes to `build/`, mirroring the source
layout (e.g. `notifications/notifications-storage.md` builds to
`build/notifications/notifications-storage.html`).

Give each deck front matter with `title:`, `author:`, `date:`, and a
one-line `description:` — that's what the site index lists it by.

```shell
just --list
just build-all
just build-presentation notifications/notifications-storage.md
just clean
```


## Styling

Decks are themed by `templates/oneproject.css`, a Slidy stylesheet
using One Project's design tokens (cream paper, Roboto/Roboto Serif,
amber accents). It's embedded into each built deck, so the output is a
single self-contained HTML file. Retheme by editing the `:root` token
block at the top of the file. Useful extras: `# Title {.dark}` for a
full-bleed dark slide, `::: handout` for speaker notes (hidden on
screen, shown in print), and `::: columns` / `::: column` for
side-by-side layout.

## Website

`just build-site` builds the whole site into `build/`: every deck plus
a `build/index.html` front door. The index's table of talks is
generated by `filters/talks.lua` from each deck's front matter
(`title:`, `author:`, `date:`, `description:`), so it never goes stale.

On every push to `main`, `.github/workflows/site.yml` builds the site
and deploys it to GitHub Pages. One-time repo setup (Settings → Pages):

1. Set **Source** to "GitHub Actions".
2. Set **Visibility** to "Private" so only organization members can
   view the site (this option requires GitHub Enterprise Cloud; without
   it, a Pages site is publicly reachable even from a private repo).

## Pandoc

Pandoc provides us a build pipeline where we translate raw digram code
blocks into SVGs.
